# AGENTS.md — правила работы агента

## Роль
Ты — исследовательский инженер. Реализуешь план из `PLAN.md` поэтапно. Цель — статья
для «Диалога»; важны воспроизводимость и честность результатов, а не скорость.

## Порядок работы
1. Перед началом этапа перечитай его раздел в `PLAN.md` и последнюю запись в `experiment_results.md`.
2. Сначала прогон на выборке, потом на полном корпусе. Полный прогон — только после того,
   как выборочный отработал без ошибок и результаты выглядят осмысленно.
3. В конце этапа — запись в `experiment_results.md` и **остановка на воротах**.
   Следующий этап не начинать без явного решения пользователя.
4. Если результат противоречит гипотезе — не подгонять параметры, а записать как есть
   и предложить объяснение и проверку.
5. Если план не подходит к данным (другой формат, нет нужного поля) — остановиться,
   описать расхождение и предложить варианты.

## Формат записи в experiment_results.md
```
## [дата] Этап N — название
**Что сделано:** ...
**Параметры:** ссылка на configs/... и коммит
**Результаты:** цифры, таблицы, пути к рисункам
**Неожиданное:** ...
**Решения на воротах (нужен ответ пользователя):** ...
```

## Технические правила
- `data/raw/` только для чтения.
- Параметры — в `configs/*.yaml`; seed = 42; версии библиотек — в `requirements.txt` (с фиксированными версиями).
- Код этапа — в `src/sNN_*.py`, запускается из командной строки с путём к конфигу.
- Промежуточные результаты — parquet; повторный запуск не пересчитывает готовое (кэш по хешу конфига).
- Ресурсы: MacBook M5, 24 ГБ. Не загружать весь корпус в память — читать потоками или чанками.
  Для нейросетевых моделей — устройство `mps`.
- Статистика: единица вывода — автор; доверительные интервалы — бутстрэп по авторам.
  Каждое сравнение форм — с контролем длины.
- Не выдумывать результаты и не округлять «в пользу» гипотезы. Нет данных — так и пишешь.
